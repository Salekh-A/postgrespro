# Дизайн-документ расширения pg_array_set

## 1. Задача

Разработать расширение `pg_array_set` для PostgreSQL, реализующее
операции над одномерными массивами как над множествами.

Функции:
- `array_intersection` - пересечение
- `array_union` - объединение
- `array_except` - разность
- `array_symmetric_difference` - симметрическая разность
- `array_unique` - дедупликация

## 2. Используемые решения и алгоритмы

### 2.1. Язык - C

**Обоснование:** по требованию задачи. C быстрее PL/pgSQL для операций
сравнения элементов.

### 2.2. Тип аргументов — anycompatiblearray

**Обоснование:** позволяет работать с массивами разных типов
(int[], text[], bool[]). PostgreSQL сам проверяет совместимость типов
двух аргументов.

### 2.3. Алгоритм — хеш-таблица

**Обоснование:** O(n) против O(n log n) у сортировки. Универсальнее —
не требует оператора `<` для типа элемента.

**Как работает:**
1. Строим хеш-таблицу по первому массиву.
2. Для каждого элемента второго — проверяем наличие.
3. Результат — массив уникальных элементов.

### 2.4. Сравнение элементов — type cache

**Обоснование:** тип элемента неизвестен на этапе компиляции
(anycompatiblearray). Type cache даёт функции хеширования и сравнения
для конкретного типа во время выполнения.

- `lookup_type_cache(elem_type, TYPECACHE_HASH_PROC_FINFO)` - хеш
- `lookup_type_cache(elem_type, TYPECACHE_EQ_OPR_FINFO)` - сравнение

### 2.5. Обработка NULL

**Решение:** NULL-массив → возврат NULL (через `STRICT` в SQL).
NULL внутри массива → ошибка.

**Обоснование:** требование задачи «NULL != NULL» — NULL-элементы
не участвуют в операциях.

### 2.6. Управление памятью

**Решение:** `palloc` / `pfree`, `deconstruct_array` / `construct_array`.

**Обоснование:** стандартный механизм PostgreSQL. `palloc` выделяет
память в контексте вызова — освобождается автоматически.

## 3. Предполагаемые тесты

### 3.1. Корректные данные

- Целые: `{1,2,3,2} ∩ {2,3,4}` = `{2,3}`
- Строки: `{a,b} ∪ {b,c}` = `{a,b,c}`
- Boolean: `{t,f} \ {t}` = `{f}`
- Пустые массивы: `{} ∪ {1,2}` = `{1,2}`
- Полное пересечение: `{1,2} ∩ {1,2}` = `{1,2}`
- Нет пересечения: `{1,2} ∩ {3,4}` = `{}`
- Дубликаты: `{a,b,a,c}` → `{a,b,c}`
- Большие массивы (1000+ элементов)

### 3.2. Некорректные данные

- NULL-массив → NULL
- NULL внутри массива → ошибка
- Многомерный массив → ошибка

### 3.3. Граничные случаи

- Оба массива пустые
- Один массив пустой
- Все элементы уникальны
- Все элементы одинаковые

## 4. Сценарии использования

```sql
-- Пересечение
SELECT array_intersection(ARRAY[1,2,3,2], ARRAY[2,3,4]);
-- {2,3}

-- Объединение
SELECT array_union(ARRAY[1,2], ARRAY[2,3]);
-- {1,2,3}

-- Разность
SELECT array_except(ARRAY[1,2,3,4], ARRAY[2,4]);
-- {1,3}

-- Симметрическая разность
SELECT array_symmetric_difference(ARRAY[1,2,3], ARRAY[3,4,5]);
-- {1,2,4,5}

-- Дедупликация
SELECT array_unique(ARRAY['a','b','a','c']);
-- {a,b,c}
